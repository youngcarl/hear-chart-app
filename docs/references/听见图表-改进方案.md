# 听见图表 · 改进方案

> 基于 `hear-chart-app` v0.1（Vite + React 19 + TypeScript）。按优先级排列，每条写清：问题 → 改哪里 → 怎么改 → 怎么验收。
> P0 = 不改会影响核心用户或评委第一印象；P1 = 体验明显变好；P2 = 有余力再做。

---

## 0. 现状速览

| 模块 | 文件 | 现状 |
|---|---|---|
| 状态与键盘 | `src/App.tsx` | 所有状态都在 App 里；快捷键挂在 `document` 上，全局生效 |
| 发声 | `src/lib/sonify.ts` | `Sonifier` 类：单点音、整条播放、提示音、`stop()` |
| 朗读 | `src/lib/speech.ts` | `aria-live` + 浏览器 SpeechSynthesis 同时输出 |
| 分析 | `src/lib/analyze.ts` | 最高、最低、整体趋势、最大单步变化 |
| 图表 | `src/components/ChartView.tsx` | 手写 SVG，对读屏隐藏，可点击选点 |
| 截图识别 | `src/lib/extract.ts` | 只有接口，按钮禁用 |

**已知未完成的检查**：React 组件还没跑过完整的 TypeScript 类型检查（原型阶段没装上 `@types/react`）。第一步先 `npm install && npm run build`，把类型错误清掉。

**建议顺序**：P0-1 → P0-2 → P0-3 → P0-4 → P0-5，然后 P1。每完成一条按“验收”跑一遍。

## P0 必须改

### P0-1 快捷键只在图表获得焦点时生效

**问题**
快捷键挂在 `document` 上。读屏软件（NVDA、争渡、JAWS）在“浏览模式”下会自己拦截方向键，按键根本到不了页面，视障用户可能完全用不了。全局拦截还会让明眼用户无法用方向键或空格滚动页面。

**改哪里**：`App.tsx`

**怎么改**
1. 删掉 `document.addEventListener('keydown', ...)` 那段 `useEffect`。
2. 把浏览类按键（← → ↑ ↓ Home End 空格 S R H Esc）挂到图表容器的 `onKeyDown` 上。图表已经有 `role="application"`，读屏软件聚焦到它时会自动切到“焦点模式”，方向键就能传进来。
3. 只保留少数全局键（B 闭眼模式、1–4 切换图表），并且在输入框里打字时不响应。
4. 图表获得焦点时读一次简短提示：“已进入图表：某城市月平均气温。左右键浏览，H 听帮助，Tab 离开。”用一个 ref 记住是否已经提示过，避免反复读。
5. 闭眼模式下把焦点锁在图表上（Tab 不能跳出去），Esc 退出。

```tsx
const onChartKey = (e: React.KeyboardEvent<HTMLDivElement>) => {
  const map: Record<string, () => void> = {
    ArrowRight: () => go(idx + 1),
    ArrowLeft: () => go(idx < 0 ? 0 : idx - 1),
    ArrowUp: () => go(st.maxI),
    ArrowDown: () => go(st.minI),
    Home: () => go(0),
    End: () => go(ds.values.length - 1),
    ' ': togglePlay,          // 见 P0-3
    Escape: () => (blind ? toggleBlind(false) : stopPlay()),
    s: () => speak(summary),
    r: () => (idx >= 0 ? go(idx) : speak('还没有选中数据点，按右方向键开始。')),
    h: () => speak(HELP),
  };
  const fn = map[e.key] ?? map[e.key.toLowerCase()];
  if (fn) { e.preventDefault(); e.stopPropagation(); fn(); }
};

<div className="chart" tabIndex={0} role="application"
     onKeyDown={onChartKey} onFocus={announceOnce} ...>
```

**验收**
- [ ] Windows + Chrome + NVDA：Tab 进入图表，← → 能逐点朗读。
- [ ] Tab 离开图表后，方向键和空格恢复滚动页面。
- [ ] 在“粘贴数据”文本框里打字不会触发任何快捷键。
- [ ] macOS + Safari + VoiceOver：同上。

### P0-2 避免“读两遍”：首次询问是否在用读屏软件

**问题**
`speech.ts` 同时往 `aria-live` 和浏览器语音输出，而浏览器语音默认开着，读屏用户会听到两遍。网页没有可靠办法检测用户是否开着读屏软件，只能问。

**改哪里**：新建 `src/lib/settings.ts`、`src/components/FirstRunDialog.tsx`，修改 `App.tsx`

**怎么改**
1. 第一次打开时弹一个无障碍对话框：`role="dialog"`、`aria-modal="true"`，打开时焦点落在第一个按钮上。
   - 问题：“你现在在用读屏软件吗？”
   - “是” → 关闭浏览器语音，只用 `aria-live`。
   - “否” → 打开浏览器语音。
2. 把选择和其他设置存在 `localStorage`，下次不再问。设置面板里可以随时改。
3. 加一个快捷键 T，切换浏览器语音开关，并读出当前状态。

```ts
// src/lib/settings.ts
export interface Settings { tts: boolean; speed: number; asked: boolean }
const KEY = 'hear-chart.settings.v1';
const DEFAULTS: Settings = { tts: true, speed: 0.32, asked: false };

export function loadSettings(): Settings {
  try { return { ...DEFAULTS, ...JSON.parse(localStorage.getItem(KEY) ?? '{}') }; }
  catch { return DEFAULTS; }  // 隐私模式等情况下 localStorage 可能抛错
}
export function saveSettings(s: Settings) {
  try { localStorage.setItem(KEY, JSON.stringify(s)); } catch { /* 忽略 */ }
}
```

**验收**
- [ ] 首次打开出现对话框，只用键盘能完成选择。
- [ ] 选“是”后，NVDA 下每个数据点只读一遍。
- [ ] 刷新页面后不再弹出，设置保持不变。

### P0-3 播放整条：能暂停、能停、播完有提示

**问题**
`playSeries` 再按一次空格只会从头重播，中途停不下来，播完也没有任何反馈。

**改哪里**：`src/lib/sonify.ts`、`App.tsx`

**怎么改**
1. `playSeries` 增加两个参数：`startIndex`（从哪个点开始）和 `onEnd`（播完的回调）。
2. `App` 里加 `playing` 状态：
   - 空格：没在播 → 从当前点（或第 0 点）开始播；正在播 → 停止，停在当前点，读出“已暂停，当前是……”。
   - Esc：停止。
   - 播完：读“播放结束”，`playing` 置为 false。
3. 切换图表、进入自定义数据、开始逐点浏览时都要先 `stop()`，并把 `playing` 置为 false。
4. 播放按钮的文字和 `aria-pressed` 跟着状态变：`▶ 播放整条` / `■ 停止`。

```ts
playSeries(values: number[], type: ChartType, step: number,
           onStep: (i: number) => void, onEnd: () => void, startIndex = 0) {
  // 只播放 values.slice(startIndex)，onStep 回调里的下标要加回 startIndex
  // 最后再排一个计时器：
  this.timers.push(window.setTimeout(onEnd, ((n - startIndex - 1) * step + 0.3) * 1000));
}
```

**验收**
- [ ] 播放中按空格立即停下，高亮停在当前点。
- [ ] 再按空格从当前点继续往后播。
- [ ] 播完听到“播放结束”。
- [ ] 播放中切换图表不会有残留的声音。

### P0-4 给评委的“30 秒体验”

**问题**
评委不会读说明书。要让他打开后 30 秒内理解这东西的价值。

**改哪里**：新建 `src/lib/tour.ts`，`App.tsx` 顶部加按钮

**怎么改**
1. 在标题下加一个醒目的按钮：“▶ 30 秒体验”。
2. 点击后按脚本自动执行：
   1. 读：“接下来请闭上眼睛，用耳朵读一张图。”
   2. 切换到“日活骤降”示例，进入闭眼模式。
   3. 播放整条曲线（能听到先升后骤降）。
   4. 读出总结。
   5. 退出闭眼模式，读：“现在你自己试试，按右方向键。”焦点放到图表上。
3. 任何按键或点击都能中断体验（用 `AbortController`）。
4. 需要“等朗读结束再继续”，所以要在 `speech.ts` 里加一个返回 Promise 的 `sayAsync`。

```ts
// src/lib/speech.ts
export function sayAsync(text: string, useTts: boolean): Promise<void> {
  return new Promise((resolve) => {
    if (!useTts || !('speechSynthesis' in window)) {
      say(text, false);
      // 读屏用户：按字数估一个等待时间
      window.setTimeout(resolve, 600 + text.length * 150);
      return;
    }
    const u = makeUtterance(text);   // 把 say() 里创建 utterance 的代码抽出来复用
    u.onend = () => resolve();
    u.onerror = () => resolve();
    window.speechSynthesis.cancel();
    window.speechSynthesis.speak(u);
  });
}

// src/lib/tour.ts
export async function runTour(signal: AbortSignal, steps: Array<() => Promise<void> | void>) {
  for (const step of steps) {
    if (signal.aborted) return;
    await step();
  }
}
```

**验收**
- [ ] 从打开页面到听完总结不超过 30 秒。
- [ ] 中途按任意键能立即停止，声音和朗读都停。
- [ ] 读屏用户也能完整走完（关掉浏览器语音时按字数等待）。

### P0-5 兼容性：微信内置浏览器、iOS、无中文语音

**问题**
国内评委很可能在微信里直接点开链接。微信内置浏览器、部分安卓浏览器对 SpeechSynthesis 支持不好，iOS 对音频和语音有“必须先有用户手势”的限制。

**改哪里**：`speech.ts`、`sonify.ts`、`App.tsx`

**怎么改**
1. **语音能力检测**：页面加载后等 `voiceschanged` 事件（最多等 1 秒），如果没有 `speechSynthesis`，或者找不到中文语音，就在顶部显示一条提示：“当前浏览器不支持语音朗读，数值会显示在屏幕上。建议用 Chrome、Edge 或 Safari 打开。”
2. **iOS 解锁**：在第一次 `click` / `touchend` 里调用一次 `ac.resume()`，并朗读一个空字符串，解锁后续的音频和语音。
3. **微信提示**：检测 UA 里有 `MicroMessenger` 时，提示“点右上角，用浏览器打开”。

**测试矩阵**

| 环境 | 发声 | 朗读 | 读屏 |
|---|---|---|---|
| Windows Chrome / Edge | | | NVDA |
| macOS Safari / Chrome | | | VoiceOver |
| iOS Safari | | | VoiceOver |
| Android Chrome | | | TalkBack |
| 微信内置浏览器（iOS） | | | — |
| 微信内置浏览器（安卓） | | | — |

**验收**
- [ ] 上表每格都实测并记录结果。
- [ ] 不支持语音的环境里有明确提示，页面不报错。

## P1 体验明显变好

### P1-6 参考音和特殊提示音

**问题**：音高只能表示相对高低，用户听不出“这个值大概有多大”。

**改哪里**：`sonify.ts`、`App.tsx`

**怎么改**
1. 新增 `playReference(values)`：先播最低值的音、再播最高值的音，并朗读“这是最低音，这是最高音”。整条播放前自动播一次（设置里可关闭），也可以按 P 手动播放。
2. 最高点和最低点在主音之后加一个短的高八度“叮”，让用户不看也知道到了极值。
3. 数据跨越 0 时（有正有负），经过 0 的位置加一个轻微的“嗒”声。

**验收**：闭眼听整条，能说出最高点和最低点大概在第几个。

---

### P1-7 手机触屏浏览

**问题**：视障同学大量使用手机，现在只能用键盘操作。

**改哪里**：`ChartView.tsx`、`App.tsx`

**怎么改**
1. 在图表上用 Pointer Events（`pointerdown` / `pointermove` / `pointerup`）实现“手指滑到哪就响到哪”：下标变化时立刻发声；手指停留 300ms 以上再朗读数值，避免滑动时一直被打断。
2. 在图表下方加两个大按钮（至少 56px 高）：“上一个”“下一个”。
3. 说明：开着 VoiceOver / TalkBack 时，系统会拦截触摸手势，这时可靠的路径是这两个按钮。在帮助里写清楚。

**验收**
- [ ] iPhone 和安卓手机上，手指滑过曲线能连续听到音高变化。
- [ ] 开着 VoiceOver 时，用“上一个 / 下一个”按钮能完整浏览。

### P1-8 总结更丰富，数字读得更准

**改哪里**：`analyze.ts`

**怎么改**
1. **峰值个数**：数局部最高点，只算高于左右谷底一定幅度（比如全距的 15%）的峰，避免小抖动被当成峰。输出“有 2 个明显的高峰，分别在……”。
2. **波动程度**：用相邻变化量的标准差除以全距，分成“平稳 / 有波动 / 波动很大”三档。
3. **首尾变化百分比**：第一个值不为 0 时，输出“比开始时增长了 33%”。
4. **数字读法**：负数读成“负 3”；很大的数自动换成“万”“亿”，比如 125000 读成“12.5 万”。
5. **单元测试**：给 `analyze.ts`、`parse.ts`、`pitchOf` 加 Vitest 测试，覆盖：单调上升、先升后降、全部相等、只有两个点、含负数、含小数。

**验收**：测试全部通过；三组示例的总结读起来自然、没有错误。

### P1-9 读屏提示精简

**问题**：图表的 `aria-label` 里塞了整段帮助，每次聚焦都会从头读一遍。

**改哪里**：`App.tsx`

**怎么改**：`aria-label` 只保留“图表标题 + 类型”。帮助文字放在一个隐藏元素里，用 `aria-describedby` 关联；或者干脆只在按 H 时朗读。

**验收**：NVDA 下聚焦图表时，只读标题和一句提示。

---

### P1-10 记住设置

**改哪里**：复用 P0-2 的 `settings.ts`

**怎么改**：语音开关、播放速度、是否播放参考音、最近使用的图表都存进去。自定义数据可以存最近一组，方便刷新后不丢。

## P2 有余力再做

### P2-11 截图识别（接口已预留）

见 README「预留：截图识别」。要点：

- 在 Qoder Sites 的函数目录实现 `POST /api/extract-chart`，返回 `extract.ts` 里定义的 `ExtractResult`。
- 模型 Key 只放在函数环境变量里；函数内做调用次数上限。
- 前端识别完先让用户核对数据表（可编辑），确认后再生成可听图表。识别错的数据比没有数据更糟。
- 失败时退回到“粘贴数据”，并给出明确提示。

### P2-12 上传 CSV 文件

`<input type="file" accept=".csv,text/csv">`，读成文本后复用 `parseData`。注意处理表头行（第一行的数值解析失败时当作表头跳过），以及 Excel 导出的 GBK 编码（用 `TextDecoder('gbk')` 兜底）。

### P2-13 多条曲线

1. 数据模型改为 `series: { name: string; values: number[] }[]`，`labels` 共用。
2. 不同系列用不同音色（正弦 / 三角 / 方波）。
3. 按键：PageUp / PageDown 切换系列（↑ ↓ 已经用于跳到极值）。
4. 朗读：“2021 年，A 课程 85 分，B 课程 72 分”。
5. 总结里加入系列之间的比较。

### P2-14 更多图表类型

散点图（x 映射时间、y 映射音高）、饼图（按占比读出各项百分比，用时长表示占比）。

## 用户测试（对参赛最有价值）

1. 联系 1–3 位读屏用户（学校特殊教育相关院系、残联、视障社群），请他们用自己习惯的设备和读屏软件试用 10 分钟。
2. 只给一个任务：“这张图里，什么时候数据最低？整体趋势是什么？”不做任何操作指导。
3. 记录：完成用时、卡在哪里、原话反馈。征得同意后截图或录屏。
4. 根据反馈改一轮，把“改了什么、为什么改”写进作品帖的“为什么做”和“用 Qoder 做出来的过程”。
