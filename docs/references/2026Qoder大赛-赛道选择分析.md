## 一、结论

**首选 Hack4Good 技术向善**，但要避开赛道内已经扎堆的“老人防诈 / 教长辈用手机 / 用药提醒”，去做空白方向。

- 三个赛道的奖金和名额完全相同：每个赛道 14 个决赛名额，正好对应 14 个现金奖。
- Hack4Good 目前 248 帖，比 LifeHack（395 帖）和 StudyHack（372 帖）少约三分之一。平均每个决赛名额约 18 帖，另两个赛道约 27–28 帖。
- 以下情况可以改选：
  - 有扎实的专业领域积累、技术较强 → **StudyHack**（避开论文 / 文献类）
  - 擅长游戏、视觉、交互设计 → **LifeHack**（避开小游戏 / 剧本 / 表情包）

## 四、三个赛道优劣势

### StudyHack 学习科研

**优势**
- 你自己就是目标用户，需求真实，也好验证
- 能展示 RAG、Agent、多模态等技术深度
- 官方示例点名了“垂直场景科研 Copilot”，专业深度有加分空间

**劣势**
- 题材最雷同：“AI 读论文 / 找文献”已有一百多个，评委容易审美疲劳
- 很多点子容易被看成“套壳 ChatGPT”
- 依赖大模型时，还要处理评委匿名访问时的调用、成本和稳定性

**适合**：在某个专业领域有积累、技术较强的人

### LifeHack 生活娱乐

**优势**
- 做起来最快，纯前端就能做好，不必依赖后端和大模型
- 评委打开 30 秒就能感受到
- 最适合发小红书 / 抖音，还能顺带拿社交传播奖

**劣势**
- 人数最多（395 帖）
- “好玩”很主观，评分波动大
- 要从 56 个小游戏里冒头，得在美术和手感上下很大功夫；“为什么做”这一节不容易讲出分量

**适合**：擅长游戏、视觉、交互设计的人

### Hack4Good 技术向善

**优势**
- 对手最少（平均每个决赛名额约 18 帖）
- “为什么做”这一节天然有分量，决赛路演最好讲
- 不一定靠技术难度取胜，靠的是对问题的洞察

**劣势**
- 赛道内部扎堆严重：老人防诈、教用手机、用药提醒这些方向再做基本没机会
- 没有真实用户洞察的话，容易被看成伪需求、自我感动
- 医疗、防灾类内容出错有风险，必须对准确性负责
- 无障碍作品本身必须真的能无障碍使用（键盘可操作、读屏软件可读）

**适合**：能找到某个具体人群的具体痛点，最好身边有人能帮忙试用

## 五、推荐项目

### Hack4Good（首推）

#### ⭐ 1. 听见图表：帮视障和低视力同学“听”懂图表

- **一句话**：视障、低视力大学生在网课、论文、作业里遇到折线图或柱状图时，用方向键逐个数据点去“听”，并听到一句话趋势总结。
- **为什么能赢**：直接服务盲人和低视力用户的作品只有 1 个（盲杖避障），把图表转成声音的作品是 0 个；正好落在官方示例“无障碍”上，又带学习场景，故事完整。
- **核心功能（MVP）**
  1. 数据输入：内置示例图表 / 粘贴表格数据 /（可选）上传图表截图，由多模态模型提取数据
  2. 声音化：音高代表数值，左右声道代表时间先后；方向键逐点浏览，空格播放整条曲线
  3. 文字层：每个数据点都能被读屏读出“标签 + 数值”；自动给出最高点、最低点、拐点和一句话趋势
  4. 闭眼模式：屏幕全黑，只靠键盘和声音完成一次读图
- **技术要点**：用浏览器的 Web Audio 纯前端实现，不调大模型也能完整演示；趋势总结可以按规则直接算出，大模型只负责润色语言；截图识别放在云函数里，失败时退回到示例和粘贴数据。全程键盘可操作，并用读屏软件实测。
- **演示亮点**：评委点“闭眼模式”，按方向键听一条曲线的起落，再听到总结。页面和帖子里都要提醒评委打开声音。
- **风险与对策**：尽量找 1–2 位读屏用户试用（可以联系学校特殊教育相关院系、残联或视障社群），把试用反馈写进“为什么做”。

#### 2. 发作时别慌：宿舍急救情景模拟

- **一句话**：室友癫痫发作或低血糖晕倒时，旁边的人该做什么、千万别做什么（比如别往嘴里塞东西），用带倒计时的情景模拟练一遍。
- **为什么能赢**：现有的急救类作品基本都是心肺复苏（约 2 个），癫痫、低血糖方向是 0 个；宿舍场景真实，谁都可能遇到。
- **核心功能（MVP）**
  1. 选择情景：癫痫发作 / 低血糖晕倒
  2. 倒计时模拟：每一步给出选项，做对做错都有即时解释
  3. 结束后生成一张可打印的“急救要点卡”，写明什么情况必须打 120
- **技术要点**：纯前端状态机 + 计时器，不需要大模型。
- **风险与对策**：每一步都要对照权威医学科普核实，并在帖子里列出参考来源；页面注明“仅供科普，不能代替专业医疗”。

#### 其他 Hack4Good 空白方向

献血 / 造血干细胞捐献（0）、罕见病 / 慢性病（1）、留守儿童（1）。

### StudyHack

#### 1. 中式英语诊所：会讲原因的英文论文润色

- **一句话**：写英文摘要的研究生或毕设学生，粘贴一段英文，马上标出中式表达、冠词、长难句等问题，每处都说明为什么错、怎么改。
- **为什么能赢**：论文相关作品很多，但标题里带“润色 / 写作”的是 0 个。
- **核心功能**：规则检测即时高亮 + 讲解；（可选）大模型给改写建议；记录你最常犯的错误类型，形成个人错误画像。
- **差异化**：讲原因 + 错误画像，而不是像直接问 ChatGPT 那样只给改写结果。

#### 2. 你自己专业的垂直工具

- **思路**：选专业里一个“高频、耗时、通用 AI 答不好”的具体任务，例如医学的解剖 / 药理机制图卡、法学的案例要件拆解、土木 / 建筑的规范条文速查。
- **为什么能赢**：医学类学习工具目前只有 2 个，法学类 1 个；专业知识是别人抄不走的优势。

#### 其他 StudyHack 空白方向

英语口语 / 发音（0）、公式识别 / LaTeX（0）。这两类都依赖语音或识别模型，要确保评委匿名访问时能稳定调用；浏览器自带的语音识别在国内网络下可能用不了。

### LifeHack

#### 1. 拼屏灯牌：几台手机拼成一块滚动大字幕

- **一句话**：演唱会应援、接机、社团招新、生日惊喜时，几个人打开同一个链接、选好机位，把手机并排摆好，拼成一块连贯滚动的大字幕。
- **为什么能赢**：演唱会 / 应援 / 灯牌类作品是 0 个；演示视频非常适合发社交平台，可以顺带拿社交传播奖。
- **核心功能**：输入文字、选样式 → 生成房间链接或二维码 → 每台手机选机位 → 同步滚动，屏幕保持常亮。
- **技术要点**：每台手机按统一时钟 + 机位编号渲染自己那一段；用一个返回服务器时间的云函数校准各手机的时钟，再提供手动微调。
- **评委模式**：评委多半只有一台电脑，要做一个“单屏预览”，在一个页面里模拟 3 台手机拼屏的效果。

#### 2. 36 张一卷：拍完要等“冲洗”的一次性胶片相机

- **一句话**：每卷只能拍 36 张，拍完不能马上看，一小时后才“显影”出带颗粒、漏光和日期戳的照片，可以整卷分享。
- **为什么能赢**：相机 / 胶片 / 滤镜类作品是 0 个；“不能马上看”的机制让它从普通滤镜工具变成有态度的玩具。
- **技术要点**：摄像头拍摄 + Canvas 滤镜 + 浏览器本地存储，纯前端就能完成。
- **评委模式**：支持上传照片（评委电脑可能没有摄像头），并加一个“立即冲洗”开关（评委不会等一小时）。

#### 其他 LifeHack 空白方向

植物 / 养花（0）、穿搭 / 衣橱（0）。

## 六、通用要点：决定能不能进前 14

1. **评委打开就能用**：不用登录，也不用填 API Key。如果要调用大模型，放在 Qoder Sites 的云函数里（有参赛者把 `dist/` 作为静态目录、`functions/` 作为函数目录），设置调用上限，并准备内置示例，调用失败时也能演示。
2. **30 秒内出“哇点”**：首页直接给示例，别让评委先填一堆东西；决赛是直播路演，要提前设计好演示流程。
3. **五个部分写扎实**：一句话定位要具体到人和场景；附上 1–2 个真实用户的试用反馈；Qoder 开发过程多截图（边做边截，别事后补）。
4. **换设备自测**：用无痕窗口、手机、另一台电脑分别打开公网链接，确认不用登录、没有报错。
5. **提前发帖**：至少留 1–2 天修 bug，别卡在最后一晚。
6. **跨赛道多交**：规则允许多份提交，只按最高分那份计奖；但“任选其一”是否允许在不同赛道各交一份没写清，想这么做先在官方群确认。
